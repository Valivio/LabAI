# Documentation Instructions

Scope: `docs/`

- Keep documentation concise and operational.
- Document only implemented behavior or explicitly approved architecture.
- Do not create journals, diaries, meeting notes, or historical narratives.
- Do not duplicate information already clear from code or configuration.
- Update architecture documentation only when module boundaries or responsibilities change.
- Create an ADR only for durable decisions that would be costly to reverse.
- Never include private source names, book titles, document excerpts, local usernames, secrets, or real filesystem paths.
- Use generic example paths such as `/path/to/LabAI-data`.
